# SHO-3048 vertical boards

Owner selected functional verticals with their own task boards, one optional vertical per delivery project, Admin-managed vocabulary, and no access inheritance.

The initial suggested names are Growth, Marketing and Founder's Office. Admins can create a real vertical task board or explicitly reclassify an existing project from Members → Project settings. No existing record is guessed or renamed by migration. Existing rows remain unclassified delivery projects, including their IDs, URLs, tasks and membership.

A vertical board remains a work container with its own Leader, members, tasks and sections. Only Admins create, rename, retire, delete, restore or change vertical-board classification. Project Leaders can link their delivery project to one active vertical in the same workspace or clear the link. A vertical label grants no board or delivery-project access. Archived vertical labels remain readable on existing links; new assignments refuse them. Converting a vertical back to delivery requires clearing its incoming links first.

Projects shows separate Delivery projects and Vertical task boards views. Delivery work can filter by vertical or Unclassified. Vocabulary labels may be read across the current workspace, while task-board details retain the existing membership/role checks.
