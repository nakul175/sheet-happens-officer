# Reviewed organisation roles — staging only

The private OS-local connector in scripts/portal-org implements SHO's native organisation policy: only a current active SUPER_ADMIN reviewer can change an active user's MEMBER/ADMIN role in the same workspace. Native SUPER_ADMIN, self, and the exact configured protected email addresses are immutable here. Email is only checked against native account protection; it is never used to find or link an identity. MEMBER does not revoke direct project membership. ADMIN inherits access across projects; the Portal UI must state that effect.

The connector is off unless APLYD_SHO_ORG_WRITER_ENABLED=1. APLYD_SHO_ORG_CONFIG must name a private regular JSON file (mode600), with runtime_environment_file (absolute private native environment file), workspace_id, reviewer_ids (exact native IDs) and review_reference. The runtime environment file must be the reviewed authority for the running native service's DATABASE_URL and SUPER_ADMIN_EMAILS. The entire policy/config digest is pinned during review and rechecked before commit. Do not enable against a service whose running configuration does not match that file. APLYD_SHO_TEST_CA is solely for the isolated fixture's pinned database CA. No real configuration or credential is included in source.

Install the new PortalOrgRoleReceipt migration only in an authorised isolated database. Run the CLI with the native Node/pg/dotenv dependencies installed and immutable source/launcher. The launcher supplies the private config path; JSON on stdin names preview/apply, exact actor and target, and for apply, desired role, expected preview and unique request UUID. There is no HTTP endpoint. Only the authorised connector OS identity may invoke it; no new database capability is granted to ordinary users.

The transaction locks reviewer and target in deterministic order, pins PostgreSQL row revisions, rechecks current authority, inserts a one-use receipt, changes only the target's orgRole, writes native notification/audit rows, verifies readback and commits. Stale/replayed/conflicting requests fail. External timeout is uncertain: reconcile the exact receipt, never retry automatically or reset users. Removing the final ordinary Admin is safe only because the current active SUPER_ADMIN is protected and retained.

Validation includes real PostgreSQL contention and rollback tests and an actual Portal Review/Save -> Accounts reviewer session -> already-open native SHO browser matrix. Runtime UI code is unchanged from the tested open-session revision; its current authority endpoint already includes orgRole. This branch changes the private connector and schema only. Production remains unchanged.
