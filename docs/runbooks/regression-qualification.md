# Regression qualification and remaining coverage

PR CI and manually requested production CI call the same `qualification.yml` workflow. Both use Node 22, a disposable PostgreSQL 16 service, the production `server.js` entry point, script tests, lint, application and story typechecks, build, suite-route preservation, mode tests, default Vitest tests and five local browser stories. Phone checks run separately for PRs and are a required dependency of the production job. No repository production database credentials are passed to qualification.

Passing these jobs is necessary, not exhaustive product acceptance. The current handover catalogue has 147 cases in `work/handover-audit-20261103/remediation/regression-traceability.json` in the engineering workspace. The older 97-case proposal is superseded for audit reporting. Every case has an assertion review, but scoped passing assertions are not full-case acceptance; consult `AUDIT-DASHBOARD.md` for the exact numerator and open gates. Map remaining steps to executable tests or a repeatable manual procedure, retain result artifacts, and mark unexecuted steps explicitly. Do not claim full coverage from collection counts or source-string policy tests.

Minimum release evidence must include the exact commit, test command and environment, pass/fail/skip counts, artifacts for failures, browser acceptance of changed journeys, role/denied-access checks, and suite smoke. Any staged external integration requires dedicated test credentials and approved consent; it must not silently run against production.

The remaining audit gate is execution and reconciliation of that catalogue against a private, representative fixture. Backup restoration and independent human onboarding are separate gates. Staging Playwright traces remain hard-off because they can contain sign-in bodies and basic-auth headers; use screenshots and redacted JSON/log excerpts instead. Production remains paused until the owner approves a reviewed candidate.

The hardening regression includes real local Accounts/BugOff PKCE/token/userinfo/status tests with synthetic client secrets: valid flows, wrong verifier/client/callback, concurrent code use, replay, expiry, revocation, bounded bodies and invalid workspace state. Redirects are inspected without following external origins. `performance-baseline.test.ts` adds a bounded100-project/10,000-task fixture, five concurrent reads, percentile/response-size measurements and exact fixture cleanup checks; its output is a baseline, not an approved SLA. CI retains JSON and browser artifacts in `qualification-results`.
