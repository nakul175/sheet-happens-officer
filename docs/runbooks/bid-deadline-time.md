# SHO-3054 — Bid submission cutoff time

NJ’s refined policy: a new Bid deadline or a changed deadline requires a date, time and valid IANA timezone. The UI visibly defaults to Asia/Kolkata (India time/IST). Existing date-only deadlines stay explicitly date-only if unchanged, including when other facts are edited. No midnight/end-of-day is inferred. Task due dates, stage rules, scheduling and filter features are unchanged. Conversion and stage-field forms only reuse the deadline controls; no conversion lifecycle refactor.

The original `DealDetails.submissionDeadline` database DATE stays intact. Nullable `submissionDeadlineAt` (TIMESTAMPTZ) and `submissionDeadlineZone` hold the exact instant and selected IANA identifier. API input adds `submissionDeadlineTime` (HH:mm), `submissionDeadlineZone`, and optional `submissionDeadlineChoice` (`earlier`/`later`). Output includes the original day, UTC instant, selected timezone and derived local time. A nonexistent local time is rejected; a repeated time requires an explicit occurrence. Resubmitting identical values preserves the selected occurrence. Undo retains/restores exact timestamp and timezone, including an upgrade back to date-only.

Detail, board, list and existing task-reminder context display the local cutoff with IANA identifier and UTC offset. Existing reminder eligibility and timing are unchanged. Overdue compares timed cutoffs against the current instant; legacy overdue keeps India-calendar semantics. Bid board sorting groups exact cutoffs first (ordered by instant), then date-only deadlines (ordered by date), then missing deadlines, avoiding an invented instant or inconsistent mixed-precision comparison. There is no new filter control or reminder scheduler.
