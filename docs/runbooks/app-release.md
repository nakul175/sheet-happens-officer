# App-only release contract

Development/production changes are currently paused. This document describes the candidate remediation; it is not permission to deploy. The production GitHub environment must have required reviewers configured by its owner before enabling this path. An environment name alone does not enforce review.

Supported entry point: manually dispatch Test and deploy on main, set deploy=true and approved_sha to the full approved workflow revision. Pushes run tests only; manual dispatch defaults to tests only. No main merge or dispatch is part of the handover remediation work.

`deploy/release.sh <full-sha>` performs a read-only migration status check before build/switch. Pending/failed migrations stop it. It never applies migrations or installs/changes schedules. Schema prerequisites must be handled by a separately reviewed, named and hash-approved runner; this app release cannot grant that approval. Schedules remain paused unless explicitly requested independently.

The draft runner has local fault-injection coverage for failed build, failed restart, rollback, release identity and configuration preservation. The release-directory guard accepts a previous release named by its full SHA or a verified legacy `e1-<story>-<full SHA>` directory whose `COMMIT` matches the suffix. It rejects an out-of-tree or symlinked previous release. Before building, it verifies the currently running previous release. If that release has its own `deploy/verify-release.mjs`, rollback uses it. Older releases without that file use the independent `deploy/verify-previous-release.mjs` shipped in the candidate. A failed pre-cut verification, missing fallback, or symlinked verifier stops before package installation or service change. When changing suite routes, sign-in origin or asset delivery, review and test **both** verifiers. The real isolated-host promotion/rollback drill and a fresh host preflight remain open. Do not use the legacy README procedure as production authorization. Restore and database operations retain their own explicit approvals.

Before upload, `reserve-release.sh` atomically creates a new destination and refuses any existing tree or symlink. This prevents rsync from deleting/replacing COMMIT, release.env or source in an already-live release before the release runner can refuse it. A failed upload may leave a reserved incomplete directory: preserve evidence and have the owner explicitly review/quarantine that inactive directory before a retry. Never delete or reuse the active target to make a retry pass.

After a verified cut, `prune-releases.mjs` only removes inactive, complete directories named by their full SHA. It protects the active and immediate previous releases, including a verified legacy previous directory. It does not automatically delete legacy, unknown, incomplete or symlinked entries. A cleanup error is reported for operator review after a healthy cut; it does not undo that cut. Retention is not a backup or a substitute for the separately verified restore procedure.
